# backfill 重设计（V1.7.0 方案）

> ✅ 已按本方案实施于 V1.7.0（见 git tag v1.7.0）。实现与本文差异：
> ① 默认 `backfill: all`；② 快路径启用即透传（auto≡on，移除年龄门控）；
> ③ checkpoint 记录 backfill 值、仅配置变化一次性回拨、存量升级只记录不回拨；
> ④ 数据起点探测采用 SHOW SHARD GROUPS（回退 count 二分）+ 空窗翻倍跳过兜底。
> 使用说明（易懂版）见 configuration.md §5.4 与 deployment.md §9。

> 目标：① 实时同步"打开即生效"，不再等历史追平；② **默认全量同步（backfill: all）**，
> 不管库内数据多早都直接同步；③ 历史回填成为可随时开启/关闭的选项，**无需清数据目录**；
> ④ 时长配置支持 `d`（天）单位；⑤ 回拨边界早于实际数据时不空爬（数据起点定位）。

## 1. 现状问题

| # | 问题 |
|---|---|
| 1 | 游标只在**首次启动**初始化（`now - watermark - backfill`），之后只能前进；想补历史必须停服、清数据目录、重启——操作重且危险 |
| 2 | 快路径被"游标追平"门控（auto 模式 WAITING→ACTIVE）：带大回填时，实时数据要等历史爬完才直达目标库，与"实时打开即生效"的诉求矛盾 |
| 3 | 时长不支持 `d`，30 天要写 `720h` |
| 4 | **空爬缺陷**：回拨边界早于库内最早数据时（如库只有 10 天数据、回拨 30 天），轮询按 5s 窗口对真空期逐个发空查询，~10 小时才碰到真实数据（不报错、不丢数据，但浪费时间与源库查询负载） |

## 2. 新语义（行为总表）

| 场景 | 行为 |
|---|---|
| 首次启动，`backfill: all`（**默认**） | 探测库内最早数据时间（§3.2），游标 = 最早数据，**全量同步直到追平实时**；快路径同时实时转发 |
| 首次启动，`backfill: 30d` | 游标边界 = now − 30d（或库内最早数据，取更晚者），从该处开始爬；快路径同时实时转发 |
| 首次启动，`backfill: 0` | 游标 = now − watermark，纯实时 |
| 运行中改配置（如 `0 → all` / `0 → 30d`）重启 | checkpoint 记录的上次值 ≠ 新值 → **一次性回拨**：游标 = min(当前游标, 新边界)；**无需清任何数据目录** |
| 运行中 `all/30d → 0`，重启 | 游标不动，继续把剩余历史爬完（"关闭"=停止扩大范围，不中断追赶） |
| backfill 不变，重启 | 游标不动（**不重复回拨、不重发历史**） |
| **存量部署升级 V1.7**（旧 checkpoint 无 BackfillNs 字段） | **只记录配置值，不回拨**——升级不触发全库重发，行为与升级前完全一致；此后改配置才按上一条回拨 |
| 快路径 | 配置启用即实时转发（`off` 除外）；不再有游标年龄门控；与轮询的重叠去重照旧 |
| 目标库 | 时序库按时间戳 upsert：新旧数据乱序到达安全；重复写入幂等（计数不重复） |

**取值**：`all`（默认，全量）/ `0`（仅实时）/ 时长如 `30d`、`1d12h`（有界回填）。

**回拨语义**：backfill 是一次性"回填边界"快照（`all`=触发时刻探测到的库内最早数据，
`Nd`=触发时刻的 now − Nd），不是持续滑动的窗口。回填完成后边界不再前移——
"持续保留最近 N 天"属另一功能（二期）。

**全量告警**：`all` 会把库内**全部**历史搬过去——若库内有数年高密度数据，同步时长按
链路吞吐计算（如 20 万点/s 搬 1 年 200k/s 密度的数据 ≈ 1 年），请按数据量评估；
对存量库建议先用 `Nd` 有界回填摸底，再决定是否 `all`。

## 3. 关键机制

### 3.1 一次性回拨（checkpoint 记录 backfill 版本）

- WAL checkpoint 增加字段 `BackfillNs int64`（上次生效的回填时长，0=未启用）。
- 启动时 `ApplyBackfillPolicy(now, backfill)`：
  - `backfill == cp.BackfillNs` → 不动；
  - 不同 → `CursorNs = min(CursorNs, now - backfill)`（**仅此路径允许游标回退**，绕过
    SetCursor 的 regress 保护），持久化新 backfill 值，日志醒目提示回拨量；
  - 旧 checkpoint（无该字段）：**V1.7 首启只记录当前配置值、不回拨**（防存量部署升级即
  全库重发）；此后配置值再变化才按上述规则回拨。
- 回拨重查的历史数据在目标库幂等覆盖；**只有配置值变化才回拨**，正常重启不会重发。

### 3.2 数据起点定位（解决"库里只有 10 天数据、回拨 30 天"）

回拨/首启后先定位"库内最早数据时间"，避免空爬：

1. **分片元数据探测**（主）：`SHOW SHARD GROUPS` 一次返回库内所有分片组的
   `start_time`，取最小值即库内最早数据时间 `oldest`——单条元数据查询、精确、O(1)；
   失败时（权限/异常）回退 count 二分探测（`SELECT count(*) FROM m WHERE time < mid`，
   ~10~15 次迭代）；
2. 边界 = `all` 时取 `oldest`，`Nd` 时取 `max(now - Nd, oldest)`（真空区直接越过，秒级完成）；
3. **空窗自适应**（辅，运行时兜底）：连续 N 个查询窗口返回 0 行时，窗口按 5s→10s→…
   翻倍（上限 1h），命中数据即复位——覆盖"回填期间又导入了更早数据"之外的正常路径
   （正常路径由 1 覆盖；新增更早数据属 §5 边界情况，需重新触发回填）。
- 正确性：探测只基于"该时间之前 count=0"的事实跳过，不跳过任何有数据区间；二分
  边界误差由轮询窗口的 +1ns 重叠与归并去重兜底，零丢失语义不变。

### 3.3 快路径门控移除

- `fast_path.mode`：`off`（仅信号）/ `on` / `auto`（**auto ≡ on**，保留别名兼容旧配置）；
- 删除 `activate_age`/`deactivate_age` 及其状态机（配置文件中残留的这两项将被忽略，
  文档注明）；
- 快路径反压门（WAL 盘占用 ≥ 黄线丢批）保留——它是真正的过载保护；
- 回填期间快路径与轮询的去重：轮询的爬行前沿距"现在"很远，去重集（15s 保留）对快
  路径数据的抑制会过期 → **回填追平的末尾会重发 ~水位窗口的数据**（幂等、计数不
  重复、带宽浪费可忽略），文档注明。

### 3.4 `d` 单位

- 新增扩展时长解析 `parseDurationExt`：`ns/us/ms/s/m/h/d`（`1d = 24h`，可组合如
  `1d12h`），**所有时长配置项统一生效**（不只 backfill）；`validateDur` 同步更新。

## 4. 边界情况清单

| 场景 | 行为 | 验证 |
|---|---|---|
| 库只有 10 天数据，回拨 30d | 探测定位到 10 天前，直接越过 20 天真空；不报错、不空爬 | 单测 + e2e |
| 库只有 10 天数据，backfill=all（默认） | 游标 = 10 天前，全量同步这 10 天 | 单测 + e2e |
| 库有数年数据，backfill=all | 全量回填（**按链路吞吐算时长，见上"全量告警"**）；真空区照常越过 | 文档注明 |
| 空库，backfill=all | 探测不到数据 → 游标 = now−watermark，正常实时轮询 | 单测 |
| 空库，回拨 30d | 探测不到数据 → 游标停在 now−30d，正常实时轮询（与空库纯实时一致） | 单测 |
| 数据比回拨边界更老（库有 60 天） | 游标 = now−30d，只搬最近 30 天（边界语义） | 单测 |
| 存量部署升级 V1.7（默认 all） | 只记录配置、不回拨，升级前后行为一致 | 单测 |
| 回填中重启（backfill 不变） | 游标不重拨，继续追赶 | 单测 |
| 回填中改小/关闭（30d→0） | 游标不动，爬完剩余 | 单测 |
| 回填完成后又导入更早的历史数据 | 轮询不会回头（游标已越过）；需重新触发回填（30d→0 重启→再 30d 重启） | 文档注明 |
| 存量 checkpoint 升级 V1.7 | BackfillNs=0；配了 backfill 即回拨一次，没配行为不变 | 单测 |
| 快路径 on + 大回填 | 实时即刻转发；目标库新旧并存（e2e 指标新鲜、总量慢涨，看 sync_delay 跟踪进度） | e2e |

## 5. 实施清单

1. `internal/config`：`parseDurationExt`（d 单位）+ `dur()/validateDur()` 接入；
2. `internal/wal`：checkpoint 加 `BackfillNs`；`ApplyBackfillPolicy(now, backfill)`
   （配置变化才回拨、绕过 regress、持久化）+ 测试；
3. `cmd/sender`：首启游标初始化改为 `all→probe_oldest` / `Nd→max(now−Nd, oldest)` /

6. `internal/sender/fastpath.go`：移除 cursor 年龄门控（auto≡on），保留 off/反压门 + 测试；

## 6. 测试计划

- 单测：d 解析（1d/1d12h/非法值）；ApplyBackfillPolicy 五态（首启/变化/不变/关闭/旧
  checkpoint）；二分探测（空库/10 天库/60 天库/边界值）；空窗放大与复位；
  fast-path 即刻激活（游标落后 30d 仍转发）。
- e2e：`0→30d` 改配置重启免清库回填、追平后计数一致；快路径+回填并行零丢失零重复计数。
- 全量 `go test -count=1 ./...` + `-race`。

## 7. 兼容性与风险

- 协议/WAL 段格式不变；checkpoint JSON 增加字段（旧文件可读，缺省 0）；
- 行为变化仅两处：快路径不再等追平（auto≡on）、backfill 改配置即回拨——均需在
  CHANGELOG/README 显著标注；
- 回拨期间源库查询负载上升（历史重查）与带宽占用上升（重发），属预期，运维按
  `sync_delay_seconds` 跟踪。
