# V1.7.3 修复说明（2026-08-16，对 audit-v172 R3a/R3b 的响应）

> 审计人：主实现方（pi agent）。对象：副审计员对 V1.7.2 的复审结论
> （docs/audit-v172-2026-08.md，R3a/R3b 两个 P2 残余泄漏）。

## 复审结论确认

R3a/R3b 均**属实并已独立复现**：

- R3a：同 (series, ts) 重复登记双计引用（`Add` 在集合插入前无条件 `idRefs[id]++`）
  → 驱逐后引用残留 → series 名永久泄漏（取证：驱逐后 series left=1）；
- R3b：`idName []string` 按 ID 单调扩容、槽位只清空不回收 → 高基数下
  200k/s×24h ≈ 170 亿槽 ≈ 270GB，"把一种 OOM 换成另一种"
  （取证：20 万 unique series 全驱逐后 slots=200000）。

## 修复（采纳审计建议的极小改动方案）

| # | 修复 |
|---|---|
| R3a | `Add` 改为仅条目**首次**插入时计数：`if _, exists := part[packed]; !exists { part[packed]=…; idRefs[id]++ }` |
| R3b | `idName []string` → `map[uint64]string`：清理时 `delete` 键，内存与活跃 series 数成正比，无槽位残留 |
