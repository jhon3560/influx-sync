# V1.7.0 审计报告（2026-08-15，第二轮审计）

> 审计范围：V1.4.3 → V1.7.0 的全部改动（A4 订阅快路径 / zstd 压缩 / backfill 重设计），
> 3314 行新增 + 250 行删除。基线：build/vet/test/race 全绿。
> 结论先给：**核心设计成立**（快路径零丢失退化框架、zstd 帧类型即算法标识、
> AppendBatch 内部分配 seq、backfill 回拨幂等论证均验证通过），但发现 3 个高危 +
> 1 个中危 + 3 个小项，其中 2 个高危在"backfill=all（默认）+ 快路径开启"组合下
> 几乎必然触发，发布前必须拦下。

## 🔴 高危

### N9（P0 运维级）：回填期去重集内存爆炸

fastDedup 驱逐基准是"游标"（`sec < cursorSec - retention`）。backfill=all（默认）
+ 快路径开启时，游标在历史区慢爬数天，而快路径持续把**实时点**登记进 fastDedup，
整个回填期间条目全部滞留（实时点 ts 远超前于游标，永不满足驱逐条件）。

量化：200k/s × 24h ≈ 170 亿条 × map 开销 ≈ **TB 级内存，必 OOM**；进程崩溃后
WAL 完好可恢复，但快路径崩溃期间推送的点只能等游标慢爬到实时区补上（延迟天级）。

修复：驱逐改**时间基准**（入口年龄 ≤ retention，默认 15s）。被提前驱逐的条目
退化方向唯一：重复转发（目标库幂等覆盖），零丢失。内存上界 = retention × rate
（15s × 200k ≈ 300 万条 ≈ 百 MB 级）。

### N10（P1 静默丢数据）：SeriesKey 碰撞

规范化键格式 `measurement|k=v|…` 在 tag 键/值含 `=` 或 `|` 时存在跨 series 碰撞：

- `{a:"x=y"}` 与 `{a=x:"y"}` → 同为 `m|a=x=y|`（**实测复现**）；
- `{a:"x", b:"y"}` 与 `{a:"x|b=y"}` → 同为 `m|a=x|b=y|`。

后果：fastDedup 误判"已转发"→ Poller Filter 删掉**从未转发**的点 → 静默丢失。
**同格式问题 V1.0 起存在于 Point.Key()**（边界去重、dense-ts 去重同样受影响，
碰撞需同 ts 才触发，概率低但存在）。

修复：键组件改**长度前缀编码**（`len:value`），Point.Key() 与 SeriesKey 同步改
（二者为内存内不透明标识，无持久化/跨组件依赖）。

### N11（P1 OOM）：空窗翻倍后首个含数据窗口可达 1h

空窗跳过（emptySkipMaxWindow=1h）豁免了 MaxWindow 上限。真空区（源库停写数周）
后数据恢复时，首个含数据窗口 = 1h 数据：200k/s 下 **7.2 亿点一次性入内存 → OOM**
（实测 windowSize 返回 1h 且 MaxWindow 被绕过；查询结果无总点数上限）。

修复：真空区**按 MaxWindow 切片扫描**——真空跳过速度不变（空片查询廉价），
任何含数据切片 ≤ MaxWindow，单轮内存有界。

## 🟡 中危

### N12（P2 恢复歧义）：DLQ payload 压缩类型未记录

DLQ 的 `payload_gzip_base64` 字段在 zstd 帧（0x04）下存的是 zstd 字节，且无类型
标记 → 人工重放时无法确定解压算法（毒丸 DLQ 与中继 DLQ 同理）。数据本身不丢，
但恢复需要"猜"。

修复：DLQMeta 增加 `frame_type` 字段（0x01=gzip / 0x04=zstd），写入时填 f.Type。

### N13（P2 语义边界）：backfill 解析边界

- `backfill: "0d"` 解析为 0 → 落入 BackfillAll（应为"仅实时"）；
- 负值（如 `-5d`）能通过 Validate（backfill 未做负值校验，validateDur 也未覆盖）。

修复：`≤0` 归入"仅实时"；Validate 显式拒绝负值。

## 已声明的设计边界（非缺陷，确认安全）

- 快路径 ns 精度守卫：ns/µs 数值域重叠（1.75e15）无法判别 → 非 ns 批整批跳过由
  Poller 兜底（Poller 经 epoch=ns 查询拿到正确精度）——安全；
- 订阅推送批超限/压缩超帧限 → 整批跳过由 Poller 兜底——安全；
- 快路径与轮询并发同点 → 双写幂等——安全；
- 反压黄线丢批 → 轮询延迟兜底——安全。

## 审计通过的核心设计（记录在案）

1. A4 零丢失框架：快路径一切退化方向（订阅丢包/解析跳过/反压丢批/去重驱逐）
   只造成"重复转发"或"退回轮询"，登记去重集仅在 WAL AppendBatch 成功之后——
   零丢失证明的核心成立；
2. zstd 帧类型即算法标识（0x04），接收端按类型解压、中继按类型透传、共享
   encoder/解码器池、炸弹防护与 gzip 路径同构——成立；
3. WAL.AppendBatch 内部分配 seq（消除 NextSeq 读-用 TOCTOU）+ 帧头 seq 重写
   （CRC 仅覆盖 payload）——成立，支持 Poller/FastPath 并发追加；
4. backfill 游标回拨：仅"配置策略变化"路径允许回退，存量旧 checkpoint 升级
   只记录不回拨，回拨安全由目标库幂等覆盖保证——成立。
